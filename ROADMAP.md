## Current limitations

- One collection day so far (2026-09-19). The live calibration scorer is empty by construction until markets that were priced before settlement settle; 207 settlements already on file are pre-tracker settlements found nested in open events and are deliberately not scored (a post-settlement price is not a forecast). First large batch: Nov 3 2026 (Los Angeles mayor, 35 Senate races, governors). Both collection loops (compact tracker + FULL universe) now run inside the single daily-collection.yml pass at 12:30 UTC.
- 2024 backtest universe = 39 settled markets from one cycle (3 core + 36 per-state Senate, 18 states). Most Senate markets opened in October 2024, so T-30/T-60 lead times cover few markets; the calibration curve is indicative, not conclusive, and the 2024 Senate map was a Republican year — group results are not exchangeable across cycles.
- The daily tracker stores traded markets only (volume > 0 or open interest > 0). Never-traded strike-ladder markets are counted in the per-day meta file but their (empty) quotes are not kept; a market that trades for the first time enters the tracker on that day.
- Poll-implied probabilities use a logistic mapping (k = 4.5) chosen in the 2024 poll backtest; it is a labelled modelling assumption, not a pollster claim. Rating 'bands' used to flag market-vs-rating gaps are a project heuristic (documented in poll-layer-2026.json).
- The 2026 poll layer is hand-transcribed from primary releases (15 entries; 4 NYT/Siena rows carry a review flag because n / MoE / field dates sit on nytimes.com pages that return 403 to the fetcher). It is not a poll average and it is not complete — e.g. Suffolk Iowa and the NYT/Siena July state polls are known but not yet transcribed. Nothing is auto-ingested.
- Exit-poll data: none used. The 2026 product (The Voter Poll by SSRS, successor to the Edison/NEP exit poll and AP VoteCast) exists but will produce data only on Nov 3, 2026.
- NO-side prices in captured 2024 candles are derived reciprocals (1 − yesClose); the raw API only publishes the YES-side series. Contest NO fills are labelled as derived.
- Poll data for 2024 ends 2024-09-12 (538 archive cutoff); the poll-vs-market comparison after that date reuses the anchor with its age disclosed.
- Two collectors run minutes apart, so the cross-check tolerates 2¢ moves; it is an agreement report, not a proof that either capture is complete. Some official results hosts block automated fetchers (irregularity #35).
- GitHub Pages serves the committed site bundle (src/data/site-data.js, ~1.2 MB); it updates only when the daily workflow commits (default branch) or a PR merges. The hand-captured Kalshi hub snapshot of 2026-09-18 is kept for cross-platform checks and is dated on the page.
- Kalshi's events feed (status=open, nested markets) returns settled (finalized) rungs inside still-open multi-market events. The collector now records their status and results and excludes them from the tradable/tracked set, but the API semantics (why finalized markets stay nested for weeks) are undocumented in the pages fetched — treat 'open event' ≠ 'every rung tradable'.
- Source registry: 125 entries verified across five sessions (six batches; 20 added in session 5 on 2026-09-19), but verification is point-in-time. Sessions 4 and 5 re-fetched their 40 new hosts on 2026-09-19 only, and the daily workflow does not re-fetch source pages, so a URL that changes later is not caught until a session re-verifies it (LIMITATIONS #18).
- Categories on the master list are an organisational label added 2026-09-19 so the site can group 125 entries; they come from a fixed vocabulary reviewed entry-by-entry (VERIFICATION.md §9b/§10) and carry no claim about a source tier or reliability ranking.
